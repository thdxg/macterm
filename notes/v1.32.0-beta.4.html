What's New

  • macterm tab new and macterm pane split take --no-focus, so scripts and coding agents can start a terminal in the background without switching your tab or moving focus. (#499)
  • Custom palette commands now run the same for everyone: in sh, or in the interpreter a first-line #! names, whatever your login shell is, and a palette can list the programs it requires:. (#521)
  • A palette's run: action no longer lands in your shell history: it runs before the new pane's shell starts, and your prompt follows when it ends. (#521)
  • A custom palette screen can show fixed rows above a listing, and any row can have a second action run with ⌥↩ or ⌥-click. (#518)
  • Every palette's description now shows under its row in the command palette, the built-in Password Manager, Worktrees and Files included. (#519, #520)

Fixes

  • In a second window showing another window's tab, splits now animate and Split Automatically picks its direction from the pane you're looking at. (#524)
  • A custom palette listing that times out, or whose screen you close, now stops right away, every command in a pipeline included, instead of sitting on "Listing…". (#522)
  • Custom palette listings now run for csh and tcsh users. (#522)
  • ⌃Z in a pane started by a palette run: action no longer freezes it. (#522)
  • A palette run: action now works while a pinned tab is active, and a relative open: path opens from the project's folder. (#522)
  • A written palette item's copy: or open: now does what it says. (#518)
  • The Files palette no longer leaves out whole top-level folders in large projects, and opens a symlinked folder as a folder rather than in your editor. (#522)
  • Pressing ⌘P while recording a keybind in Settings → Keymaps now records it instead of opening the palette. (#522)
  • Backspace in another window or in the quick terminal no longer steps back out of this window's palette screen. (#522)
  • Search ranks equally good matches in the same order everywhere, and treats a word starting with . or - and accented letters the way fzf does. (#522)

Notes

  • Custom palettes written in nushell or fish syntax stop working. Write them in sh, or start a command with #!/usr/bin/env nu.
  • A palette file with an unknown or misspelled key, in: on a copy: or open: action, or an invalid export name now fails to read, with a message naming the node and key, where it used to be silently ignored.
  • In a remote project, a run: action is still typed at the host's prompt, without the palette's exported variables.
